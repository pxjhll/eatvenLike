# 店铺与员工模块化制作体系：已确认需求与边界

日期：2026-11-11。分析基线：main `9bc1b20`。

## 目标

新增使用已有能力的店铺，主要完成场景模块装配、美术接入和流水线配置；新增普通员工，主要完成资源与角色定义接入。真实需求需要新能力时，扩展公共系统一次，之后可以复用，未启用它的旧店维持原有行为。

## 已确认的产品约束

- 奶茶店是角色大小、初始属性和基础行为的蓝本。
- 同一员工进入不同店铺，使用同一份全局基础定义。店铺选择名册、岗位和招募顺序，不私配基础属性。
- 奶茶店基准：员工逻辑高度128，顾客110，顾客基础走速170；统一逻辑单位和镜头后，同一窗口的角色显示大小与移动观感一致。
- 奶茶店已有员工基准：cat/gray_cat为walk112、work1、carry2；rabbit为104、1、2；raccoon/bear为88、1、3；fox为96、1.6、2。
- 不同员工允许有全局定义的差异；已有升级作为显式倍率或加成叠加。
- 新店主要改变美术、布局、设备、菜谱、生产关系、交付策略、解锁和经营配置。
- 拿取、放下、搬运、抵达、等待、操作等基础能力具有稳定语义；新业务通过组合能力表达。
- 多步骤取餐、多路生产合流是扩展验收例子，不据此增加正式菜单、设备或经营功能。
- 扩展兼容包括旧行为回归、公共接口语义、数据版本和存档延续。
- 模板覆盖原画到运行场景的制作过程；美术资产粒度与功能模块粒度分开。
- 美术生产遵守 `docs/art/scene-art-production-rules.md`；资源复用、固定组合、FigCraft确认和源稿隔离要求继续适用。
- 以真实需求逐步抽象，不提前制造统一脚本语言或万能流程解释器。

## 系统边界

| 部分 | 责任 | 不归该部分负责 |
|---|---|---|
| 全局角色定义 | 基础属性、动作资源映射、能力声明 | 店铺招募价格和岗位数量 |
| 共享运动与动作 | 路线、位置、抵达、动作进度、暂停和动画对应 | 决定某道菜的配方 |
| 业务流程 | 任务先后、条件、物品需求、交付策略 | 自行移动画面角色或复制导航 |
| 生产依赖 | 材料输入输出、分支、合流、容量、占用 | 顾客动画 |
| 场景模块 | 美术、占地、操作端口、排序点、交互区 | 店铺专有角色基础值 |
| 店铺实例 | 装配与引用上述定义 | 复制一套公共控制逻辑 |
| 验证与版本 | 模块合法性、兼容性、行为验收、存档迁移 | 静默修复或清空不兼容存档 |

保留并逐步使用现有 SpecShop、SpecStep、SpecStaffKind、ShopSession、WorkerState、RuleNav、ShopAnchors、内容指纹和存档刷新机制。生产合流先审计复用现有 consumes/produces 与 serve 依赖能力，不把它们视为不存在。

## 运动和流程协议

业务提交目标和动作请求；共享运动系统产生路线、位置和抵达事实；共享动作系统推进动作及结果。规则侧持有权威状态，表现侧消费快照并插值，不独立推进业务抵达。

空间区分客区、后厨、通道连接和角色权限。柜台明确员工放餐点、顾客取餐点与接单位；座位明确接近点、坐姿显示点与餐盘点。占地考虑脚底半径；无路应报告或等待，不回退成穿物直线。

原子动作需明确前置条件、完成条件、占用和预留、取消释放规则以及可保存状态。业务扩展采用显式能力与策略声明，不增加按店铺ID分支。

## 兼容与迁移

1. 首先冻结奶茶店当前可接受行为，包括确定性规则轨迹、角色基准、真实界面与存读档。
2. 提取公共实现时，奶茶店已有配置的数值、事件顺序、库存和业务结果维持一致。
3. 将煎饼摊和第三店校准到奶茶基准属于已授权的行为调整，必须列出与旧基线的有意差异，不能伪称完全等价。
4. 流程扩展没有启用时，原流程状态与结果不变；新状态字段必须有明确版本和默认语义。
5. 存档升级使用既有备份和内容刷新机制，保留经营进度、身份、升级和合法订单；有新增不可兼容状态时定义专门迁移，不以改文件名或清档替代。
6. 奶茶店未定义的员工种类先保留现有可用性，统一接入时使用全局登记的能力档，禁止因查不到角色而悄悄套用名册第一项。其数值选择记录在角色任务的评审结果中。

## 验收

- 同一角色跨店的基础属性、逻辑尺寸和同视口显示尺寸一致。
- 员工、顾客全程不穿占地或越过权限区域，到位后才进入相应动作。
- 暂停和现有各个倍速下，规则、位置、抵达与动画保持一致。
- 线性、并行合流和多物品交付通过独立夹具验证；缺料、拥堵、取消与读档不丢物或复制物品。
- 工位移动时占地和端口随模块移动，场景导出的空间数据与运行数据一致。
- 使用已有能力新增演示店，只添加配置、资源与场景，不修改公共运行代码。
- 使用已有动作新增演示员工，只添加角色定义与资源映射，不修改角色控制逻辑。
- 原画资产清单能对应到资产、模块与玩法配置，正式资源与制作源稿分离。
