# Dispatch candidate and selection policy

## Intent and scope

Continue the approved dispatch-decision architecture work after PR76. Extract candidate construction, score arithmetic and winner selection into a stateless policy. This preserves behavior; no scheduler balance change or newly confirmed defect is claimed. One PR stacks on codex/machine-progress at b70824156ea0c0aa5567acb70dea70941085c1bd while PR76 remains open.

`game/rules/dispatch_policy.gd` extends RefCounted without class_name. It exposes eight static APIs below and has no persistent state. Its only definition dependency is the existing immutable SpecDispatch passed explicitly to the methods needing weights. No Rules/host/context/callback, SpecShop, navigation, RNG, event bus, services, cache or serialization. Explicit worker/job dictionaries are borrowed inputs or result references, never retained by the module. No generic capability wrapper or whole Rules clone.

Rules retains supply/demand and topology queries, eligibility and candidate enumeration, recipe/ticket planning, path lookup, the estimator's work-versus-hop branch, the outer greedy allocation loop, and actual reservation/execution. In particular each reservation must be followed by fresh candidate enumeration against the now-updated stock/reservations. Do not precompute all assignments, reorder candidates, sort ties, cache candidate lists or change the cost model. Inventory, WorkerState, Sales, Completion, MachineProgress, save/content/UI/asset files remain unchanged.

## Exact policy APIs

1. `transport_candidate(kind: String, source: String, destination: String, item: String, carry_count: int, available_count: int, free_count: int, priority: float, belt: String = "") -> Dictionary`: count=mini(carry_count,mini(available_count,free_count)); if count<=0 return fresh empty dictionary. Otherwise return {kind, src:source, dst:destination, item, count, priority, belt, order_id:-1} in that exact legacy key order. Do not apply a shelf-specific cap here.
2. `serve_candidate(job: Dictionary, order: Dictionary, pour: String, dispatch: SpecDispatch) -> Dictionary`: mutate and return the same supplied candidate. Set count=1, order_id=order.id, pour=pour, then priority += wait_bonus(dispatch,order.wait). Preserve all other fields/aliases; order and definition remain unmodified. Called only for a nonempty eligible candidate, after Rules decrements seats_left when appropriate.
3. `exact_count(job: Dictionary, count: int) -> Dictionary`: if job empty or job.count<count return fresh empty dictionary; otherwise set job.count=count and return that same job. No new positivity/clamping/eligibility policy.
4. `wait_bonus(dispatch: SpecDispatch, wait: float) -> float`: minf(dispatch.wait_bonus_cap,wait*dispatch.wait_bonus_per_second), with no extra normalization.
5. `score(dispatch: SpecDispatch, worker: Dictionary, job: Dictionary, travel: float, work_time: float) -> float`: throughput=float(job.count)/maxf(0.1,travel+work_time); return (job.priority+throughput*dispatch.throughput_weight-travel*dispatch.travel_penalty)*(1.0-worker.fatigue*dispatch.fatigue_weight), with the original arithmetic ordering. No input mutation or finite/fatigue guards.
6. `consider(best: Dictionary, worker: Dictionary, job: Dictionary, value: float) -> void`: if value>best.score, set best.score=value, best.worker=worker, best.job=job. Otherwise no mutation. Rules creates a fresh {score:-INF,worker:{},job:{}} each allocation round. Preserve strict comparison, first tie, original job/worker reference identity and the all-minus-infinity no-selection case. Only the caller-local best record changes.
7. `route_choice(options: Array, source: String, destination: String) -> Dictionary`: old belt choice loop: skip empty and wrong src/dst. Select if best empty OR job.priority>best.priority. Return selected original job reference, or fresh empty dictionary. First ties remain selected. Do not reuse score-based consider, whose initial -INF policy differs.
8. `fallback_pot_choice(options: Array) -> Dictionary`: old new-ticket fallback loop: skip empty; if best empty OR option.priority>best.priority assign option.duplicate() (shallow). Return selected shallow copy or fresh empty. No option mutation. Preserve first ties, nested aliases and independence of top-level priority/ticket fields.

## Rules integration and sequencing

`_candidate` evaluates carry(worker), _available(source,item), _free(destination) in the original order and passes these to transport_candidate. If result empty return immediately. SHELF then queries _cup(item)/_shelf_item_free, applies the old second cap and rejects nonpositive result. Do not query shelf capacity early or for other destinations.

`_jobs` keeps all station/order/post/seat eligibility and candidate ordering. Replace only the successful serve candidate field/priority enrichment with serve_candidate, after the same seats_left decrement. `_exact` remains a forwarding facade. `_new_ticket_job` retains open order prefix grouping, _start_stage, ticket construction and _ticket_job. Only its applicable fallback loop calls fallback_pot_choice, and its successful priority expression uses wait_bonus before attaching the same ticket. Follow priority is overwritten; serve priority is incremented.

`_allocate` retains the current outer workers.size rounds, worker traversal and idle filter, job traversal/empty filter, two path lookups and no-route guard, travel formula and the exact `job.kind == "work"` duration predicate. Then call score and consider for that candidate. At the end of a round break on best.job empty, otherwise _reserve(best.worker,best.job) once. Subsequent rounds regenerate candidates; no reservation or walking moves into the policy. `_run_belts` retains cooldowns, _courier flag window, _append_pack_jobs and reserve/take/shipment order; replace only its winner loop with route_choice. Single-worker dispatch is unchanged.
