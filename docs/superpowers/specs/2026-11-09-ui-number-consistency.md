# UI 数值一致性设计

用户已批准在 PR 中落实 2026-11-09 的分析结论。工作目录使用当前 D:/Tes/eatventure，在 codex/ui-number-consistency 分支完成，不新增 worktree。

## 目标与边界

界面展示明确区分基础属性、当前有效属性、计算单价、实际结算、机器基准操作时间与整单时间。规则执行和展示共用数值查询，不能让 UI 再实现一套倍率公式。保留现有店铺数值、培养成本、菜谱和结算方式；修复遗漏的时间调参属于本次目标。奶茶继续小数累计，煎饼继续整单取整，不为消除显示差异改变经济规则。

本 PR 同时包含已实现并通过回归的四项审查修复：按店铺配置选择存档文件且保留旧档、口味组与回退菜完整检查开放条件、重开确认准确说明员工清空范围、重开记录器重置会话及采样状态。

## 规则层接口

- 当前有效员工属性查询使用现有 stat/walk_speed/skill/carry，统一返回 walk/work/carry；个人等级未实现，员工卡片改为明确的店内培养进度，不伪造个人等级。
- 人工动作耗时查询统一接受站点、基础秒数、员工（可省略，代表操作倍率 1）和 fixed。fixed 仅忽略机器升级，仍允许机器时间调参；锅的取料人工步骤不应用烹饪升级。保留两种履约方式当前默认倍率下的执行结果。
- 机器时间快照包含基准秒数和单位。批量锅为每锅，自动组合台为每批，人工操作为每次或数据单位；按实际执行的工序来源选取基准动作。界面标明不含员工加成和行走，不能宣称完整服务时间。
- 报价查询同时提供计算单价和明确的结算方式。无附加选项的单点收款从现有 order_price_single 查询得出，奶茶仍展示带小数单价并说明累计规则。
- 自动锅在开工时记录 duration，当前 progress 由本次 duration 和 remaining 得出；中途升级或调参只影响后续动作，进度不回退。兼容没有 duration 的现有单人模式存档。

## 展示层

- 员工页数字与属性条取有效属性，培养状态随员工所属区域显示，不将区域培养写成个人升级。
- 调参说明和设备升级耗时从同一时间快照读取，使用正确单位，避免 0 秒和手工台遗漏调参。
- 售价行统一保留有效小数。计算价和单点实收明确标注；配料加成不再描述成整份价格倍率，升级后的具体值通过真实规则预览查询。
- 解锁面板的当前报价使用有效价格；固定说明中的基础价明确标注为基础价，避免与动态报价混淆。
- 当前已完成工作的改动保留。测试、探针与真实玩家存档/调参文件隔离。

## 验收

用失败用例覆盖员工培养和调参后的可见数字、机器时间滑杆真正影响完整订单、无培养基准与实际动作计时、茶叶升级后的价格精度、配料部分涨价、单点/带选项整单取整、奶茶小数累计、锅中途升级进度，以及旧状态恢复。先看到失败，再落实接口和 UI。

全量测试、两家店和引导/HUD/音频 GUI 回归、布局和营业基准检查必须通过。需要修改旧快照时，保留规则层营业基准，仅更新有明确错误且已用真实执行验证的 UI 断言。完成后独立审查、提交、推送功能分支并向 main 创建 PR，不直接推送或合并 main。
