# 进度安全第一批设计

用户已选择“先做进度安全三项”：跨店提交、业务状态完整校验与原子恢复、Profile 未来版本保护。当前分支 codex/progress-safety 基于 PR #64 的 8803810；后续独立 PR 以 codex/ui-number-consistency 为 base。使用 D:/Tes/eatventure 当前目录，不新增 worktree、不修改/合并 PR #64。

## 范围与现有契约

保持店铺内容、经济、存档正常格式与现有逐帧恢复行为。保留 ShopSave 对新增/删除数据 ID 的兼容合并，以及旧单人锅 duration 的一次性恢复。第二阶段的通用会话上下文、稳定 reset 总线、配置能力矩阵和履约引擎拆分不在本批。

## 1. Profile 持久化提交和版本保护

Profile 的写入应有可故障注入的单一持久化入口，并保留现有 JSON 表达方式。finish_shop(record) 返回 Error：先持久化候选 Profile，成功后才提交内存；失败保持 shop、records、fresh_shop 和原文件不变。提供同等原子语义的切店和确认新店初始化方法，避免场景先修改字段后 save。

加载未来版本时显式报错并禁止任何 save/finish/reset/切店写回。已加载后磁盘被替换为未来版本，也不能覆盖。支持现有 version=1 文件；对缺失版本的旧文件采取有测试说明的兼容默认。错误 JSON、版本类型、非整数版本或不支持版本不得被静默写坏，至少保留原件并返回明确状态。不要为本批引入通用迁移框架或改写历史 Profile 的浮点编码。

## 2. 应用层进度协调

新增独立的进度协调服务，明确 Profile、ShopSave 和场景之间的提交顺序。场景仅在提交成功后删除旧档、发出切店信号和切换场景；失败时店内状态、当前存档、Profile 与交互仍保留，显示可理解的失败信息，重试不重复添加结店记录。

调参跳店也必须先确认店内保存成功，再提交目标 Profile；失败不前进。

fresh_shop 是已经持久化的初始化意图：先成功保存空的新店，再持久化清除 fresh_shop，最后允许玩家进入。任何一步失败都保留可重试标记；确认标记失败时不得允许玩家产生随后会被重置掉的营业进度。若需要阻止启动，给出简洁的失败/重试界面，不允许自动存档或退出回调覆盖原存档。写 Profile 成功后删除旧店失败最多留下旧副本，不应回滚已持久化的新进度或再次记录结店。

故障边界包括切店 Profile 写失败、新店写失败、fresh_shop 确认失败以及重试/重启。测试使用临时文件和注入的 Profile/Store，所有录制、调参、引导状态与真实用户文件隔离。

## 3. 业务状态校验与原子恢复

从 ShopRules 提取独立只读业务状态校验器，不依赖 UI、不写文件、不修改 live rules。验证顶层外形之外的实际读取结构：

- rng/event_rng 恰好两个整数；标量和向量数字有限；阶段与等级范围有效。
- 员工、名册、任务、路径和单人工序的必要字段、类型、索引；员工 ID 唯一且部署 ID 能引用名册。
- 站点状态、输入输出与预留计数的形状；动态字典允许其规定的开放键集合。缺失的新增机器使用默认值、已删除机器的孤立顶层数据继续忽略；活动任务不能引用不存在的目标。
- orders/customers/queue、带上物品、事件、加成等运行时集合的必要结构和引用；不要硬编码任何店名、机器名或菜名。
- 合法旧档中可选的 duration 等字段与本批前已有兼容行为保持一致，不因新校验误拒正常完整回放存档。

先在临时候选状态完整构造、验证成功后再替换 live rules。无效输入返回非空错误，live 的 to_dict、随机数、导航、加成、事件订阅和内存对象保持原样；不产生 GDScript 运行时错误。成功后仍保持 workers/roster 的引用一致性以及规则事件监听绑定到实际 live rules，而不是临时构造对象。

ShopSave 对合法编码但无效业务状态应设置 last_error，并按现有隔离策略保留原文件；不得返回部分应用的状态并宣称成功。坏文件无法隔离时禁止盲目覆盖。

## 验收与发布

以本轮架构审查的四个仓库外探针作为原始复现参考，不让正式测试依赖外部路径。先建立失败回归，再实现；正常逐帧存读档、两店营业基准和 GUI 必须保持通过。

新增 Profile/切店安全与业务状态验证测试应纳入 run_all；故障场景验证原文件字节、内存快照、事件信号和重试结果，不只断言返回码。加入真实 ShopSave 外层编码/校验和正确但内层状态非法的加载测试。将用户数据目录或所有文件服务隔离后运行 GUI 回归，避免再次生成真实调参/录制文件。

独立规格与代码审查后提交、推送新分支并创建依赖 PR #64 的独立 PR，不自动合并、不推送 main。使用本机 Godot 4.6.3 验证并明确版本；项目现有 CI 用 Godot 4.7。
