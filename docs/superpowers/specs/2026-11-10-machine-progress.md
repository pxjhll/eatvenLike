# Machine progress kernel

## Purpose and boundary

Continue the approved architecture sequence after PR75 by extracting automatic machine time progression from ShopRules. This is a behavior-preserving architecture change, not a confirmed gameplay bug fix. One PR stacks on codex/fulfillment-completion at 2d37c780fff180277ce630fac8dde0bc3bad214b while PR75 is open.

`game/rules/machine_progress.gd` extends RefCounted without class_name. It has no persistent state, host, callback, event, navigation, RNG, service, SpecShop or numeric-query context. It receives explicit station records and primitive values. It may preload rule_inventory.gd solely to reuse its pure static stock() query; no inventory instance is constructed or retained. Inventory, Sales, Completion and WorkerState remain unchanged. No source/cache/serialization copy is added to production.

Rules keeps shop station iteration order, eligible block/auto/pickup/unlock filtering, recipe output mapping, duration queries and orchestration order. The module owns local time, inventory processing effects and phase transitions. Rule's assignment of processing_item is the boundary between selecting recipe output and applying automatic timing.

## Exact APIs and semantics

1. `pause_for_stir(station: Dictionary, before: float, points: Array) -> bool`: Iterate points in their existing order. On the first before < point and station.progress >= point, set progress=point, remaining=duration*(1-point), phase="stir", return true. Otherwise return false without mutation. No sorting, epsilon or normalization.
2. `advance_handoff(station: Dictionary, block: String, delta: float, stir_points: Array) -> String`: Perform the old eligible station's complete per-tick processing and automatic input selection. If processing>0 and phase not awaiting_take/stir: save before progress, remaining=maxf(0,remaining-delta), progress=1-remaining/duration. For batch_pot, pause_for_stir runs before completion and returns immediately with empty string if paused. At remaining<=0.000001: batch_pot sets awaiting_take; others add processing to output[processing_item], set processing=0, processing_item="", phase="ready". Set progress=1 in either completed case. Then, if processing==0 and block!=batch_pot, iterate input in insertion order and select first positive count. Set processing=1 for pickup, otherwise full selected input count; subtract from input, return selected input key. No output/duration query or automatic timing assignment yet. If no input and Inventory.stock(station)==0, set phase="idle"/progress=0. Return empty string for every no-start path. Preserve all other historical fields and container aliases. Completion and next batch input consumption may happen in the same tick, but next batch receives no progress time until the next tick.
3. `begin_automatic(station: Dictionary, seconds: float) -> void`: Set duration=seconds, remaining=duration, progress=0, phase="working". Rules has already bound processing_item. Preserve counts/input/output/reservations/history. This second phase preserves duration queries observing consumed input, selected output and previous phase exactly as before.
4. `advance_single(station: Dictionary, delta: float) -> void`: Only when phase=="cook", subtract delta from remaining, without clamping. At remaining<=0 set phase="done". No epsilon, progress recalculation, output or stock effect. Preserve every other field.

Rules `_pause_for_stir(id,station,before)` stays as forwarding facade. `_update_machines()` filters stations exactly as before, calls advance_handoff once with points only for batch_pot. When a nonempty input key returns, assign processing_item=input for pickup or _auto_output(id) otherwise, then call begin_automatic(station,machine_seconds(id)). Do not query output or duration for no-start states. The single station loop remains between customers and workers in _tick_single(), calling advance_single only for eligible unlocked batch pots. No change to arrivals, dispatch, belts, worker work, settlement, save format or UI/assets/content.
