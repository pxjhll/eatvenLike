# 欢迎页与片头

用户已同意在 `codex/opening-video` 接入：欢迎原图 → 点击解锁游戏音乐并播放无声片头 → 保持视频最后一帧 → 按参考动作弹出金色“开始营业”按钮 → 进入原有存档对应店铺。每次进程启动播放一次，店铺切换不重播。

## 边界

新增启动场景，不把片头覆盖在已经运行的店铺上。欢迎阶段不创建营业会话、不写营业存档；片头音乐通过现有 ShopAudio 播放，保留音乐偏好，同曲目进店不重启。原视频音轨不使用。

公共能力仅包含启动阶段管理、跨场景选曲以及媒体播放适配。规则、调度、员工速度和营业 UI 不改动。欢迎图完整等比显示，底部原图按钮有可访问的真实点击区域，支持触摸、鼠标及键盘。播放期间拒绝重复启动，最终进店只能触发一次。

## 媒体

欢迎图使用用户指定的 940×1672 PNG。第一段视频保留 720×1280、24 fps；网页用去音轨的 H.264 CRF23 MP4（faststart），Windows 用去音轨 Theora q7 OGV。最后一帧从对应视频中提取；不依赖停止播放器来保持画面。最终按钮使用透明 SVG 金色底板、圆角、阴影和强调线，复用游戏现有公共 UI 字体与焦点样式，由小放大后稳定，约 0.45 秒。

网页用浏览器原生 video，只在播放期间覆盖启动画幅；JS 桥接负责 started/finished/failed 和释放，不创建额外音频播放器。Godot 负责欢迎、最后一帧和最终按钮。Windows 使用 VideoStreamPlayer。完成或失败时先显示静帧，再移除播放器；视频失败提供明确提示且允许进入店铺。

网页导出排除原生 OGV，MP4 作为导出目录独立文件复制，不放入 PCK。普通 Windows 打包保留 OGV，不打入网页 MP4。源稿和临时分析留在 `_work`。

## 验证

启动状态测试覆盖：欢迎时不创建店铺/读写存档、重复点击、片头完成冻结、按钮动画后才可进店、播放失败可继续、重复进店防护、不同长宽比按钮对齐。音频测试验证同曲目交接不重播及音乐关闭偏好。运行现有规则与音频回归；验证实际 Web PCK 体积和导出场景一致；浏览器验证媒体加载、第一击解锁、播放完成和进店，窗口验证原生视频及最终画面。
