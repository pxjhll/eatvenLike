# 店铺 UI 基础框架

用户已在当前对话批准：先将现有试玩合并 main，再实施上一轮讨论的 UI 框架；本轮直接继续执行。

## 范围

- Godot 4.6.3，保持现有奶茶店家具、生产规则、员工获得/培养价格和会话存档边界。
- 主界面顶部仅保留店名、金币、售出杯数、倍速及菜单入口；底部为店铺、建造、员工、招募。
- 静态 UI 框架（顶部、导航、遮罩、弹层）使用可在 Godot 编辑器修改的独立 Control 场景和容器布局，员工卡根据当前名册生成。
- 员工面板展示头像、类型、等级、当前工作、属性与培养。员工卡可拖入场景，拖起时收起面板；点击场景员工可显示简短操作条。
- 招募面板接入现有普通招募，支付实际金币并增加实际员工；高级招募仅显示未开放，无随机抽卡、稀有度、付费货币或假奖品。
- 建造面板展示机器、传送带、布局的明确未开放状态；本轮不实现摆放或改动家具。
- 暂停、运输模式、重新开始和旧版入口归入菜单。重新开始需游戏内二次确认，防误触清空会话；ESC、关闭和遮罩可退出面板。
- 面板打开时经营继续；用户暂停状态不被打开/关闭面板更改。面板与导航区域阻止穿透到场景员工，隐藏员工卡不能成为拖拽来源。
- 720×1280、360×640 和 1280×720 下，UI 位于可见边界内且保持可读；横屏面板可独立于竖屏场景使用更大的显示尺寸。
- 收拢场景中的冗余任务文字，仅选中员工显示详细任务；保留工位必要状态和拖拽反馈。

## 验证

运行现有完整模拟回归、实际 GUI 导航/招募/培养/菜单/拖拽验证，并检查主界面、员工、招募、建造、小屏和横屏的实际渲染截图。回归不能依赖隐藏按钮点击。
