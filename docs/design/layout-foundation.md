# 布局与员工移动：计算基础预留

2026-10-28 用户方向：当前采用预设布局；后续可能开放自由布局。员工可在前后厅走动并承担多个任务，一个员工可轮流完成所有必要人工步骤，多名员工分担工作。这一方向更新了此前“后厨员工固定工位、不计算行走时间”的规划。

本次扩展现有 `ShopGridDef`，仅提供可复用计算。当前关卡配置、员工调度、运输计时、存档和美术摆放仍沿用原有行为；没有启用自由摆放或真实行走计时。

后续员工和运输的玩法决策见 [员工任务与运输玩法草案](staff-task-logistics.md)：使用共享任务池，综合能力、优先级、路径距离和软疲劳选取空闲员工；人工搬运和传送带按每段生产连接配置，不再要求上一环节的固定员工负责送货。软疲劳只影响派工倾向，具体综合评分尚在规划中。

## 已提供的计算

- 店铺范围：后厨和前厅区域的并集；区域之间的空隙不可通行。
- 障碍：`blocked_cells` 表示固定墙体等障碍；调用时另外传入家具不可行走占地。
- 占地：按物体左上格、整数占地宽高、顺时针四分之一圈旋转生成占用格。图片像素尺寸不参与计算。
- 旋转：同一局部坐标变换可用于占地外的操作点、输入口和输出口。
- 摆放验证：检查无效尺寸、越界、固定障碍、家具重叠。调用不会修改占地；移动验证时调用方应排除自己的旧占地。
- 静态寻路：四方向最短路径，不斜穿墙角，路径包含起点和终点；不可达返回空路径。
- 行走估时：路径边数除以格/秒。已经在目的地时为零，不可达或移速非正数时为 `INF`。
- 显示换算：逻辑格与显示位置双向换算。显示每格大小由调用者提供，不读取 PNG 大小。

例如 1×3 格长桌始终占三个格子。制作密度为 256 像素/格时，其地面占地参考框为 256×768 像素，但立面、阴影、透明区可以超出该框。全图尺寸不能用来反推占地。

## 接入前仍需确定的数据

1. 为当前美术场景标定逻辑地面网格、墙体、门口、家具占地和操作点。现有 `grid_pos`、`view_pos` 与美术预览并未统一，不能直接把它们当成已经校准的导航地图。
2. 每个可移动对象保留稳定实例 ID，定义原始占地、朝向、操作点和物流端口；美术锚点、图像偏移单独配置。搬动不会改变设备的库存、升级和生产身份。
3. 初期从预设布局生成占地；以后玩家摆放生成同样的数据。只有最终确认摆放时才提交更改并重算路径，不能让预览拖动直接改变生产状态。
4. 摆放提交还要验证入口到必要操作点可达；仅调用 `placement_error` 不能保证通道畅通。本次提供了寻路能力，未实现全店布局事务。
5. 员工调度增加“认领任务 → 行走 → 操作 → 完成/释放”阶段。到达前不推进人工加工。自动机器加工阶段释放员工，多个员工不能重复认领任务或抢同一操作位。
6. 后续布局变动需要处理正在行走的员工、已认领任务、不可达目标和传送带连接；再把动态布局、员工位置和阶段加入版本化存档。

## 刻意留待后续实现

此基础不负责自由布局 UI、运行中移动设备、员工碰撞和动态避让、任务优先级、全店任务池、动画、美术接入或传送带重连。也不会根据新路径长度自动改变现有 `length_cells` 或生产经济参数。

当前小店地图使用广度优先搜索足够；地图和查询量显著增大时，可在保持同一返回约定的前提下替换为 A* 或缓存路径。

验证用例覆盖旋转占地和外部操作点、越界与重叠、墙体门口绕行、不可达任务、行走耗时，以及显示像素与逻辑占地相互独立。

验证结果：新增 6 个用例先验证失败，再实现计算；完整回归共 74 个用例，0 个失败。
