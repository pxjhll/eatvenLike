# 员工任务与运输玩法草案

状态：持续玩法规划。2026-10-29 更新。独立美术试玩版已实现流动任务、运输、能力培养、软疲劳，以及拖拽切换坐班/流动。旧版 GameSim 与试玩版的实现范围见下文。

## 已确认的方向

- 当前采用预设布局，后续可能开放自由布局；两者共用占地、通路和操作点计算。
- 员工分坐班和流动两种岗位模式。坐班绑定指定岗位；流动可以跨工位、跨前后厅完成工作。一个员工时默认流动，轮流完成必要人工步骤，多名员工自动分担。
- 使用共享任务池。任务不绑定上一环节的员工；从空闲、能执行任务的员工中选择接单人。后续讨论将单纯就近派工调整为综合考虑能力、优先级、路径距离和软疲劳；具体评分权重尚未确定。
- 两个环节之间没有传送带时，需要人工取货、走到下游机器并放货。
- 有传送带时，员工把货放上带即可结束这次放货任务，运输由传送带继续完成。
- 制作和搬运是不同任务。流动员工完成制作后也可立即成为搬运候选人，但不强制由他搬运；坐班员工不参与跨工位搬运。
- 疲劳采用软疲劳，只影响后续派工倾向，不降低实际移速、操作效率或搬运量，不强制停工休息。

距离建议使用实际可走路径，而非穿墙的直线距离。需要先到取货点的任务，比较员工到取货点的距离；从取货点到下游的路程用于验证整段任务可执行并估算总耗时。

## 坐班与流动（本轮记录）

用户明确提出将某个动物锁定在一个岗位，随后确认直接拖放：拖入工位就是坐班，拖到空白位置就是流动。该交互现已接入独立美术试玩。

| 岗位模式 | 可领取任务 | 位置与行为 |
|---|---|---|
| 坐班 | 绑定岗位的人工操作任务 | 固定在该岗位操作点，不接其他岗位工作，不承担跨工位搬运；无任务时原地待命 |
| 流动 | 搬运、配送，以及没有坐班人员的人工工位操作 | 在允许的共享任务池中，按能力、任务优先级、实际路径和软疲劳综合派工 |

- 岗位锁定先于综合评分。岗位有坐班动物时，该岗位的操作任务只交给绑定动物，流动员工不会因距离更近或能力更高而抢走操作任务。
- 锁定的是操作岗位，不独占整个工位的物流。流动员工仍可送入原料、取走成品、搬到下游或放上传送带。
- 操作点、取货点、放货点分开设置，避免坐班员工挡住配送交接。
- 玩家解除岗位锁定后，动物才重新加入流动任务池。软疲劳不会自动解除锁定或把坐班动物调走；锁定期间按原有能力工作，无活待命时恢复疲劳。
- 单员工默认流动，保证能独立完成生产与服务。若玩家把唯一员工锁定坐班，其他环节可能因无人搬运而等待；界面应给出缺少流动员工的提示，不擅自解除玩家安排。
- 首版坐班主要用于人工煮茶、手工加料等人工工位；自动调奶、自动封口默认不需要专人坐班。
- 操作型通常适合坐班，速度型和力量型通常适合流动。这是效率上的选择，不是动物类型的硬性岗位限制。

示例：流动员工送杯到加料台 → 坐班狐狸完成加料 → 流动员工取走 → 送到封口机或放上传送带。狐狸留在操作点等待下一次加料任务。

### 拖放交互与改岗交接

- 可从场景内动物身体或底部员工卡开始拖动；普通点击仍只选择员工，不改变岗位。
- 拖到煮茶台或左侧加料台：锁定该人工岗位。拖动期间显示工位范围、操作点和目标反馈。
- 拖到可行走空白地面：解除坐班，恢复流动；松手时员工立即放到落点所在的通行格，从这里重新接活，不再从旧位置走来。
- 自动调奶、自动封口不接受坐班；墙体、家具障碍、场景外和已被其他员工锁定的岗位均拒绝落位，并保留原安排。本版不自动交换两名员工。
- 拖到人工工位时，松手后直接放到该工位操作点并锁定岗位，防止其他员工同时绑定。
- 2026-10-29 玩家反馈后调整：有效拖放立即中断当前任务，携带货物退回原来源，释放本次任务的取货、目的地、操作和订单占用；未完成的人工操作不产生成品，物料保留在原工位。员工随后从落点重新接活。
- 携带期间为货物保留来源的退回空间，避免多人生产补满原来源后，拖放退货导致超出容量。无限原料源的退回同步撤销已领取原料计数；取消配送不结算销售或任务完成。
- 已经放上传送带的货物继续运输，独立加热或自动机器已经开始的加工继续运行；拖走员工仅中断该员工当前尚未完成的任务。
- 坐班员工只执行本站操作；原料/成品的取放点与操作点分开，运输仍交给流动员工。
- ESC、触摸取消和窗口失焦取消未提交的拖拽。触摸绑定发起手指，其他手指不得接管、松手提交或改变目标。
- 单员工坐班导致没有流动员工时，持续提示搬运将等待，玩家可拖回空地恢复。

煮茶现已分离为本站人工投料、独立加热、本站人工取茶；搬原料进来和把茶汤送去调奶机是独立流动任务。这样煮茶坐班具有实际操作任务，不需要离开工位运输。

## 一段连接的两种交接

| 连接方式 | 上游出货后的任务 | 本次任务完成条件 |
|---|---|---|
| 人工搬运 | 到上游取货 → 携带 → 走到下游 → 放入进料区 | 货物已交付下游 |
| 传送带 | 到上游取货 → 放入连接传送带的入口 | 货物已成功放上传送带 |

交付到下游进料区，不代表下游的人工加工也已完成；下游根据原料和设备类型提出自己的操作任务。自动加工时不占用员工，机器完成后再发布必要的取货或搬运任务。

对于制作点就在传送带入口旁的场景，刚完成制作的员工在距离上有优势，可以继续放货；仍需结合能力、任务优先级和软疲劳选人，不与该员工永久绑定。

## 软疲劳规则（已确认采用）

- 疲劳表示持续工作负荷，工作时增加，空闲时恢复。建议按工作时长与负荷累计，不以接单次数作为唯一依据。
- 疲劳只对接单评分产生有限惩罚，促使其他合适的空闲员工分担工作。不会直接降低员工培养得到的跑速、操作效率或搬运量。
- 派工时评估疲劳，已领取的任务照常做完；不会因为疲劳变化在途中反复转派。
- 只有一名可用员工时，即使疲劳高也继续接单。没有因疲劳低分而禁止接单的硬门槛，不要求员工强制休息。
- 自动机器独立加工时，员工若已经释放任务并空闲，可以恢复疲劳；若正在执行其他任务，则继续按实际工作累计。
- 疲劳上限、增长恢复速度和评分权重留待数值验证。分担工作不要求所有员工接单数量相同，也不应抹平培养带来的效率差异。

## 能力与派工评分（讨论方案）

用户提出能力三角、优先级、任务距离和疲劳共同决定派工。能力三角建议采用速度、力量、操作效率，具体属性定义和权重尚待确定。

建议先确定任务的优先级，再为任务评估合适的空闲员工：速度影响行走耗时，力量影响单次搬运量和批量完成耗时，操作效率影响人工操作耗时；再结合工作偏好、实际路径和软疲劳。避免同一种能力既计入实际耗时又被重复过度加权。

批量补货任务应保留需求数量，不能全部拆成单件后只比较第一件谁先送到，否则力量型员工的搬运量优势无法进入派工判断。紧急单件交付与批量补货可采用不同任务目标。具体优先级策略仍需进一步细化。

## 一人和多人的表现示例

- 一人默认流动：人工投料煮茶 → 搬运茶汤到自动调奶机 → 手工加料和必要搬运 → 转去服务。自动机器加工期间，该员工可以离开处理其他任务。
- 两人均流动：A 正在手工加料，B 可以搬运已有成品；A 空闲后也可领取服务任务。
- 坐班与流动混合：A 坐班加料台，B 负责送入杯子、取走成品和其他流动任务。A 不离开加料岗位送货。
- 更多人：在各自岗位权限内并行执行可用任务。不能重复领取同一任务，也不能同时占用同一操作位。

## 建议作为首版实现约束

以下为技术和行为建议，尚未全部由用户逐项确认，不代表新增玩法已启用。

1. 任务必须就绪：需要的货物存在、目标已开放、员工能到达取货点和放货点、相应容量可用。
2. 派工同时认领任务并预留资源。人工搬运需预留源货物及下游容量；上带任务需预留可用的入口接收位置。不得把货物直接从源库存复制到目的库存。
3. 取货之前，货物仍在原出口；取走后属于员工携带的在途库存；放下后归下游输入或传送带。人工在途也必须计入现有成品限额，避免绕过“包含在途的口味容量”规则。
4. 下游或传送带堵住时，尚未取走的货物留在上游出口。员工不无限抱货等候；已取货后的布局变动、任务取消和路线失效，需要单独规定安全交回或重新规划规则。
5. 接单后完成当前原子任务再派新任务。不能因为另一个任务变近而在路上反复换目标；自动机器等待阶段不属于员工持续占用的人工任务。
6. 综合评估接单人，不再只比较距离；评分相同时建议按等待时间、稳定任务 ID 和员工 ID 确定顺序，以保持可重复的结果。长期远处任务是否增加优先级、顾客临近失去耐心时是否插队，留待后续确认。
7. 家具占地、员工操作点、取货点、交付点分开定义；不能用贴图中心或 PNG 外框直接替代。

## 实现状态与差距

旧版 GameSim 已有人工操作请求、请求认领与释放、机器输出缓冲，以及传送带物流；后厨请求按工作区分配，前厅请求受固定岗位限制。旧版尚无共享全店的综合评分派工、软疲劳、人工携带库存或独立搬运任务。

旧版 `ConnectionDef` 和 `ProductionSystem` 将每条生产连接按传送带处理，出口会自动推上带。向旧版统一接入新规则时，应保留稳定的生产连接关系，再给每段连接定义人工或传送带运输；明确人工放货与设备自动吐料的差异，避免同一份货同时被员工和自动物流取走。

独立美术试玩版 `TeaPlaytestSim` 已在现有美术场景运行单口味制作、人工/传送带运输、综合评分派工、能力培养和软疲劳。导航已通过 `ArtPlaytestLayout` 以子格标定并接入行走，相关范围见 [试玩验证说明](../qa/tea-art-playtest.md)。

坐班/流动双模式已接入试玩，默认员工流动，可拖拽绑定煮茶或加料，并在忙碌时安全交接。验收见 [拖拽岗位验证](../qa/staff-posts.md)。旧版原有前厅岗位绑定不等于新坐班系统。完整图素占地定义、自由布局和运行中路线重算仍需后续实现。

## 下一轮需要细化

- 自动机器的默认出货：员工取货上带，还是特定机器具备自动吐料端口。
- 一次搬运几份，以及原料桶和成品杯是否使用相同携带规则。
- 生产、搬运、服务的优先级，以及防止远处任务长期无人处理的规则。
- 能力三角的属性定义、任务评分权重，以及软疲劳的增长、恢复和影响范围数值。
- 人工上料、卸料、工作和运输之间如何拆分任务，避免重复计算同一放货动作。
- 坐班交互的后续扩展：岗位交换、多人岗位、持久化岗位安排，以及自由布局时的操作点与物流点重算。
