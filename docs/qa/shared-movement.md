# T05 共用移动与抵达协议验收

日期：2026-11-11。基于已提交T04（8b0d24c），分支codex/tea-baseline-shared-staff。T05按本轮用户指令单独提交并推送，包含此前尚未推送的T04提交。

## 交付

员工和顾客复用RuleMovement的距离预算、路径索引和完成判定。空路径表示阻路等待，不能被当成抵达。非空legacy员工路径保留原有浮点运算顺序；奶茶冻结轨迹继续作为兼容门槛。

SpecLayout显式声明motion_version。0保留旧业务与顾客表现；1启用共享运动，必须提供grid导航、原生单位倍率、权限区域、队列和顾客端口。三家正式店尚未切换到1；它们的场景占地和员工属性迁移分别属于T08–T10。本次不宣称第三店的实际穿物和360走速已经解决。

v1导航使用半径12逻辑单位的脚底方形包围盒，保守覆盖脚底圆。权限区域与总地面取交集，未知权限不可通行。起终点和每段连线都检查占地、权限边界和已解锁障碍；同格目标保留真实起点，非中心点不能通过替换格中心切墙角。障碍开闭变化清路径缓存，从记录的真实位置重新寻路；无路时保留任务与预留等待。人物之间的动态避让不在本阶段范围。

v1顾客状态由规则拥有，包括入口、排队、取餐、等位、就座和离店。顾客逻辑走速统一取共享配置170；员工速度仍取对应全局/店内定义与升级计算，然后换算原生坐标。正式店员工定义统一按T09/T10迁移。

三种既有业务均消费规则抵达事实：serve与single顾客到队位才可接单；自取分支等待顾客到取餐端口才交付；送桌分支的员工走到座位放餐；serve顾客到座位才进入就座/用餐；handoff堂食计时等顾客实际抵达座位。serve队首已被接待时，其他员工不能越过它接待还在后排的人。serve的旧walk_left/walk_total仍保留为兼容字段，v1抵达判断不使用它们，也不能把它们当作新的路径ETA。

ShopView输出深拷贝运动快照；ShopPlay的v1分支直接绘制规则位置，不消费GUI delta推进路线。坐姿是已到接近端口之后的美术偏移，不反向决定规则抵达。堂食组件只刷新家具和桌上物品，不再创建第二套运动角色。阻路员工在规则中仍持有待完成的请求，画面使用静止姿态；帧动画速度使用逻辑单位，避免素材密度改变动作速度。

当前规则仍使用原有0.1秒固定步长；本阶段没有新增预测或插值器。后续若平滑表现，只能插值规则快照，不能恢复视图自行判断业务到达。

## 存档与扩展边界

仅v1序列化movement{version:1,customers:{...}}。员工的motion记录包含version/goal/profile/topology；客户另外持有身份、目标、座位、离店状态及路线。状态验证拒绝未知版本、未知权限、非法路径索引、伪造抵达、目标与路径终点不符以及跨越禁区的剩余路线。

没有运动字段的旧档按原业务阶段重建客户位置和路线，保留经营、身份、员工、订单、库存与计时。原顾客没有权威坐标，无法恢复历史GUI的精确像素；serve行走阶段使用旧剩余时间比例在当前安全路径上重建，已就座者采用座位端口。第一次替换旧文件前使用既有pre-content备份，并核对原字节。未来运动版本保护原文件并拒绝覆盖。新状态在业务事件回调中也可独立验证、保存和读回。

v0内容指纹忽略新增且未启用的布局字段，保留A阶段奶茶指纹；v1将运动配置纳入内容指纹。T06可以复用begin_move/advance_move和客户ready，而不重新实现路径、距离或到达。
