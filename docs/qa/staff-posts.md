# 拖拽坐班与流动验证

日期：2026-10-29。当前独立奶茶店美术试玩，现有家具和图素位置保持不变。

本页保留岗位生产回归的原始范围。当前经营版本还支持待派遣员工直接拖入店内，以及员工/店铺保存恢复，见 [tea-business.md](tea-business.md)。

## 操作

- 按住场景中的动物或「员工」面板中的员工卡，拖到煮茶台/左侧加料长桌：坐班。拖起卡片时面板自动收起。
- 拖到可走空白地面：松手立即放到目标通行格，并恢复流动；从落点开始运动，不再从旧位置走过来。
- 拖到人工工位：松手立即放到该工位操作点并坐班。拖动预览显示实际落位位置。
- 已有人坐班的岗位、自动机器、墙体和其他无效地面会拒绝拖放，保留原安排。
- 忙碌时拖放会立即中断当前任务，手中货物退回来源，再从落点重新接活。未完成的操作物料留在原工位；订单和库存占用同时释放。
- 搬运期间保留来源退货容量；已经启动的独立机器和传送带运输继续运行。
- ESC 或触摸取消可撤回拖拽。多指不能抢走当前手指的拖拽。
- 唯一员工坐班后，会提示缺少流动员工；拖回空地即可恢复。

## 验证结果

- 完整回归99个用例，0失败；新增直接落位、任务各阶段取消退货、来源容量保留、多员工反复拖放及隔离地面拒绝验证。
- 坐班位置、岗位独占、拒绝自动/占用/非法位置、忙碌操作与携带物品中断退款、解除后恢复服务、软疲劳不解锁、满库存煮茶等均已覆盖。
- 原有11个试玩模拟用例继续通过，默认全流动的单人闭环和两种运输仍可运行。
- `tests/render_staff_posts.gd` 实际发送鼠标和触摸输入：身体/卡片拖拽立即落位、普通点击、空地解除、岗位占用拒绝、自动机器拒绝、墙体拒绝、ESC、缩放后的拖放、携货中断归还与重开。
- 触摸回归覆盖单指身体/卡片、第二指移动/松手不提交、所属手指系统取消不改岗，以及没有员工候选时失焦清理指针。
- `canvas_items` 缩放模式下，测试输入从逻辑画布坐标换算到窗口像素；使用明确的事件刷新保证注入顺序。
- 真实岗位 GUI/渲染验证0失败。
- 独立审查发现的触摸指针和取消问题已修复并回归。

现有退出时的Canvas/ObjectDB资源告警沿用此前记录；无新增运行中脚本错误。

## 范围

仅支持煮茶、加料各一名坐班员工；不自动交换岗位，不保存试玩会话。收银台下方与工作区隔离的地面不能放员工。旧版GameSim不改变。员工间动态避让、自由布局与多人岗位仍属后续工作。最新 UI 与额外遮挡验证见 [shop-ui.md](shop-ui.md)。
