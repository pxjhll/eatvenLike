# 三店空店完店标定

2026-11-12 状态：以下结果与基线记录的是加入酸梅汤前台直售之前的配置。用户要求先关注局内节奏，最终通关时间暂缓；新增菜单后尚未重新标定本报告的总时长，不代表当前配置已通过46分钟门禁。局内短测见 `shared-shop-rhythm.md`。

日期：2026-11-11。工具 `tools/shop_progression.gd`；当前确定性基准 `tests/baselines/shared_shop_progression.json`。这项验收补足此前 T12 只有短测报告、没有标定的缺口。

## 目标与方法

用户目标为奶茶、煎饼恢复原时长，小炒约46分钟。原历史基准分别为2133.1秒与1365.1秒，小炒目标2760秒，验收范围均为目标±5%。员工初始属性、尺度、移动和动作协议不变。

从空店、正式起始金币和初始名册开始，使用店铺固有种子（奶茶20261025、煎饼0、小炒11），每0.1秒推进真实规则。机器人在第1秒首次访问，之后每60秒访问一次，每次最多6笔购买：原料箱、解锁、忙碌时招募并实际部署、最便宜的可用升级。升级超过下阶段费用的1/4时攒钱；独占手工台满负荷时优先升级。排队不超过一人时按真实规则发传单。分区店按最高岗位负载判断招人，先补后厨再补前台；无分区店按共享负载和共享名额招人。没有额外金币、免费员工、提速倍率或跳过经营任务。

机器人策略不是唯一玩家策略。完成时刻、首单、每阶段解锁、逐笔交易、分岗忙闲tick、收入与销量都写入报告。小炒另对种子42、84执行完整回放，与默认种子11一起强制验收；不能缺少、不当标注或只挑有利种子。所有完成状态必须可独立加载；任一种子未完店、目标超出±5%、当前基准或内容指纹不一致均非零退出。相同机器人在改前与改后正式配置上执行；改前报告内容指纹已与上一版短测基线逐店核对一致。报告版本2增加`audits`，购买策略不变。

## 正式配置调整

- 奶茶：阶段解锁和设备/物料升级成本增加约15%，按整数四舍五入；员工培养、菜价、配方、客流不改。
- 煎饼：7种餐品的各价格部分增加15%，保留两位小数；耗时、设备费用、客流和任务不改。
- 小炒：招募价60/120/160/220改为30/60/80/110；炒制配方12/14/16秒改为6/7/8秒，装盘7秒改为3.5秒，代表工位耗时同步。宫保鸡丁刚解锁阶段需求占比30%改为60%，蛋炒饭20%、前两种盖饭各10%；末阶段扬州炒饭需求占比25%改为50%，其余四道主食各12.5%。初始两人和岗位、设备/升级费用、售价、客流间隔、米饭与例汤批次/库存、配方输入输出、任务数量不改。

小炒原600秒双人采样中，唯一后厨忙了588秒，前台空闲522秒。单独改调度优先级改善有限；采用上述单店配置，缩短手工串行段并降低补齐后厨的门槛，同时减少末阶段等新菜随机点单的时间。不修改全局员工速度，不复制角色或调度实现。
