## 范围、契约与状态归属

原生 Godot 4.7 / GDScript，沿用唯一 App autoload、GameSim 时钟与中介。Production 拥有实体工序/传送带/库存；Workforce 拥有工作区和人工步骤；FrontHall 拥有来客/订单/共享封口服务；Economy 拥有金币/累计营业额；ShopProgress 拥有菜单、任务和阶段。UI 读取复制快照、只提交命令，不另存金币或权限真值。

后厨权限唯一来源为 ShopProgress.stage_index 与只读 ShopConfig.kitchen_unlock_stage 的比较。默认 0 保留面包店；奶茶店设 1。未开放时厨房工序/物流不推进，但前厅柠檬水仍持续生产销售。生产改造和厨房调岗在命令验证阶段拒绝，失败不扣金币、不改派工/连接/进度。购买下一阶段锅位是有意保留的入口：先检查营业额、金币和锁定机位，再沿既有命令一次提交，更新菜单阶段后自然打开厨房。

普通画面和调试 HUD 都隐藏未开放厨房机位/信息；厨房调岗按钮隐藏，前厅可见生产/传送带的改造按钮禁用。前厅购买新菜按钮始终可见，显示营业额/价格条件。HUD 和世界/UI 的订阅配对断开；HUD 重绑测试确认旧模拟不能继续更新显示。

所有茶店配方、价格、时间、数量、库存、来客、门槛、升级/并联费用和任务均在 content/tea/tea.tres。运行时不修改 Def。通用业务系统没有奶茶或机位 ID 分支；呈现层的饮料图标映射允许具体资产 ID。

## 可玩流程

1. 无旧档的新 Profile 按 starting_shop_id 进入 tea：经营柠檬水，厨房隐藏且核心命令拒绝越权。
2. 累计营业额 120 且金币至少 60 时，在前厅购买珍珠奶茶/锅位，菜单增为两种饮料，厨房开放。
3. 拖小熊到后厨：从生珍珠供料，经员工装锅、18 秒煮制、员工取出，得到实体熟珍珠；熟珍珠与奶茶基底混合后进入备料架。
4. 柠檬水与奶茶共用前厅人工封口/服务请求、员工和队列；第二锅提高煮制产能，但前厅仍会形成等服务队列。调走厨师会耗尽珍珠，调回后恢复。
5. 卖出柠檬水 10 杯、奶茶 20 杯，菜单与任务完成；保存与重建后继续同一状态。

目录保留 bakery 为旧 index 0，tea 追加 index 1；旧 Profile.from_dict 不应用新建默认店。新建进入 tea 不会将旧面包店档案静默映射到茶店。tea 为目前最后的店，本次不展开下一家店或第二店流程。
