# 现有美术场景内的奶茶店玩法试玩

用户已要求直接使用现有美术场景做可玩版本，避免灰盒与实际画面的落差。当前分支 codex/tea-reference-art；保留已有未提交美术整理，不重新生成美术，不重建 shop_art.tscn，不移动家具。

## 本次可交付行为

- 新入口 presentation/tea_playtest/tea_playtest.tscn，F5 默认进入。使用现有 shop_art.tscn 实例，只在运行时替换静态员工和示例饮品。
- 原料柜 → 人工投料煮茶、独立加热、人工取茶 → 自动调奶 → 左侧长桌人工加料 → 自动封口 → 货架 → 前厅交付。
- 一名员工可跑通完整订单；可雇佣第二、第三名员工。沿用现有猫、浣熊、狐狸图素，分别体现速度、搬运量和操作效率。
- 人工搬运真实携带库存，取放和行走独立计时；下游容量及源货物在接单时预留，不重复派工。
- 共享任务池综合能力、实际路径、任务紧急程度和软疲劳派工。软疲劳不改变真实移速或操作效率，空闲恢复，不阻止单人继续接单。
- 可切换上带运输和人工运输，已在途的货物正常完成；不会复制或丢失货物。画面展示传送带上的真实物品。
- 可选择员工并培养其擅长属性；真实能力和操作效果同步变化。显示任务、疲劳、订单、售出量、金币、工位状态和库存。
- 暂停、继续、重新开始均可交互。试玩会话独立，不将试玩业务状态和进度写入旧存档；保留旧版游戏入口。旧版进入试玩前保存其旧版会话，避免在试玩中退出程序时丢失旧版最新进度。

## 约束与裁定

- 第一版只做珍珠奶茶闭环；其他口味、完整解锁经济、保存试玩进度、自由摆放和方向骨骼动画不在本次范围。
- 煮茶采用已有讨论建议的人工投料、加热时可离开、人工取茶。可以配置时长，不要求员工一直守着自动加热。
- 保持现有画面几何，采用 20 显示单位导航小格（与 256 像素/占地格的图素密度分离）；根据家具底部标定障碍，预留操作点。
- 人工动作先沿用现有完整姿态图素，通过行走摆动、方向翻转、手持物、工位进度和状态文字反馈。不是新角色动画资产交付。
- 自动调奶/封口自行加工；需要人工把输出交给下一环节。传送带模式通过人工上带后自动运输。
- 不把原始静态示例杯当作真实库存。所有新增可见杯子必须来自模拟。

## 实现边界

独立的 TeaPlaytestSim 作为本次可玩规则原型，复用现有 ShopGridDef 的导航基础；表现仅调用模拟接口、读取状态。现有发布版 GameSim、配方、存档格式不更改。玩法确认后再迁移和统一模拟，避免在试错期间直接改变现有进度与经济。

## 验证

模拟回归覆盖单人完整出品、多员工、人工/传送带两种路线、库存守恒和容量预留、培养和软疲劳、切换物流时在途交付。渲染检查真实场景中员工行走、遮挡、携带和杯子运输，验证暂停、雇佣、培养、切换和重开按钮。完整现有测试回归并输出实际游戏截图。
