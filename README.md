# eatvenLike

当前默认进入**奶茶店美术试玩**，使用现有分层美术实际运行员工制作、搬运和配送。底部为店铺、建造、员工、招募入口；员工面板查看和培养伙伴，招募面板邀请普通员工，建造与高级招募显示未开放。拖动物或员工面板中的卡片到煮茶台/加料台设为坐班，拖到可走空地恢复流动；支持软疲劳派工、人工/传送带运输及1/2/4倍速。试玩会话暂不保存。

当前验证引擎为 Godot 4.6.3（GDScript）。入口是 `presentation/tea_playtest/tea_playtest.tscn`；顶部菜单包含暂停、运输方式、重开和“进入旧版”，旧版和静态美术预览也有“试玩”入口。UI 框架独立为 `presentation/tea_playtest/shop_hud.tscn`。操作及验证见 [UI 框架验证](docs/qa/shop-ui.md)、[拖拽岗位验证](docs/qa/staff-posts.md) 和 [试玩说明](docs/qa/tea-art-playtest.md)。独立图素与场景说明见 [art/reference/README.md](art/reference/README.md)。

下文保留旧版经营流程与项目结构的历史说明，数值不代表当前默认试玩。

这一版新档从**奶茶店空店开局**：前厅柠檬水台和柜台是价格牌，点一下花钱摆上；员工栏里招人，把卡片拖到柜台上岗，服务员就开始卖柠檬水（PXJ-46）。营业额到门槛后买下煮珍珠锅，后厨和奶茶线开放，后厨仍是 v1.1 的固定机位（布局模式见 PXJ-47）。面包店（白面包 + 切片吐司）作为旧店保留在存档里，PXJ-47 做布局模式时删除。

现场是 2D 3/4 灰盒：能看到物料输送、员工装卸/服务、备料库存和顾客排队。点击工位可升级或启用并联，底部是员工栏，列表图标可展开原有调试 HUD。新手引导、移动端手感和正式美术仍待后续制作。

灰盒资源包含六类工位、兔子/小熊/小猫三套动画、顾客、四种物料及 UI 图标；切片机在店里是灰色虚影，累计营业额到 600 后可以买下；小猫资源暂未接入。独立打开 `presentation/graybox/asset_gallery.tscn` 可查看资源。

源图、PNG 和动画帧信息见 `art/graybox_manifest.json`；生成方式与授权见 `art/CREDITS.md`。渲染与输入验收记录见 [docs/qa/README.md](docs/qa/README.md)。

## 奶茶店这家店（首店）

| 东西 | 怎么来的 | 占位数字 |
| --- | --- | --- |
| 柠檬水台 | 前厅位点，点价格牌解锁 | 10 金；出品台（饮水机式）：不配员工、不囤杯、不限量，服务员过去现打一杯 2 秒，升级提速 |
| 柜台 | 前厅位点，点价格牌解锁 | 20 金；所有顾客在这里点单，接单 + 递杯 2 秒，最多站 2 人 |
| 员工 | 员工栏「招人」，拖到工位上岗 | 15 / 25 / 40 / 60 金；一人一岗，拖到满位就是换岗，拖回员工栏是下岗 |
| 奶茶线 | 营业额 300 后买煮珍珠锅（60 金） | 生珍珠箱 → 煮珍珠锅 → 调配 → 备料架 → 柜台，售价 24 |

开局金币 50，正好够柠檬水台 + 柜台 + 第一个人。数字都在 `content/tea/tea.tres` 里，直接在 Godot 里编辑。

## 白面包这条线（面包店，旧内容）

面粉箱（外购，每 3 秒 1 份）→ 传送带 → 面团台（自动，2 秒）→ 传送带 → 烤炉（员工装入 0.8 秒 → 烘烤 4 秒 → 员工取出 0.8 秒）→ 传送带 → 备料架 → 前厅柜台（员工服务 1.5 秒，售价 10）。
烤炉旁有一个并联槽（120 金启用），面团台到两台烤炉默认轮流送、跳过堵住的一路。顾客约每 4 秒一位，等 18 秒没人接待就走。任务：白面包卖出 30 份。

## 第 2 道菜：切片吐司

累计营业额到 600 后，点灰色的切片机花 200 金买下（PXJ-40）：
烤炉 → 传送带 → 切片机（自动，3 秒）→ 传送带 → 备料架 → 同一个柜台卖，售价 18。
烤炉出口同时连着备料架和切片机，轮流送，跳过堵住的一路；玩家可以点传送带断开某一路来改分配。
买下后来客间隔从 4 秒变 3.2 秒，点单 6 成白面包、4 成吐司；新增任务「切片吐司卖出 50 份」。
菜单做全、两条任务都完成后店铺完成，可以换店。不做任何优化大约 5 分半到 600、15 分钟左右完成（数值都是占位，细调见 PXJ-35）。

所有数字都在 `content/` 的 .tres 里（占位值），直接在 Godot 里编辑。

## 相对契约 v1.2 的进度（PXJ-46）

- 已做：`FrontSpotDef`（前厅位点，点价格牌解锁）、`UnlockFrontSpot` / `HireStaff` / `SwapStaff`、`AssignStaff` 改成「工位或工作区」、`StationDef.DISPENSER`（饮水机式出品台，没有库存，不走预留）、`ShopGridDef`（首店 6×5 后厨 + 6×5 前厅，手写 .tres）。
- 还没做：布局模式、设备栏、自动传送带、一键部署、加料台与口味货架（PXJ-47 / 48）。后厨因此仍用 v1.1 的 `SlotDef` / `ConnectionDef` 固定机位，后厨员工也仍按工作区派工；前厅已经是按工位。
- `ShopGridDef` 目前是手写的 .tres，店铺场景模板和 `@tool` 导出脚本等后厨真的能摆了（PXJ-47）再做。

## 相对契约 v1.1 的补充

- Def 多了 4 个类：`SlotDef`（机位：工位 Def + 是否 LOCKED + 并联槽 + 网格坐标）、`ConnectionDef`（允许的连接与长度）、`ShopStageDef`（解锁表一行）、`GameCatalog`（店铺顺序和员工）。
- 备料架作为连接终点，id 固定为 `shelf`。
- `SetConnection` 带一个 `connected` 参数，接上或断开；断开后线上物料原地不动，可用 `ClearItems` 清理。
- 为满足不变量 9（步长无关），每 tick 在第 4 步新请求提出后再派一次工，人工和机器完成时把本 tick 剩下的时间接着用。步长 0.05 和 0.1 之间产量相差不到 1 件；步长放到 0.2 时，因为传送带交付等仍有一个 tick 的交接，十分钟大约少 2 个面包。
- 存档：Godot 的浮点文本解析不能逐位还原，存档里的 float 编成 8 字节十六进制；JSON 不排序键（字典顺序也是状态）。这样才能做到不变量 10 的「完全一致」。
- 顾客只在还没人接待时会因耐心耗尽离开，所以目前不需要 Workforce 中途释放请求。
